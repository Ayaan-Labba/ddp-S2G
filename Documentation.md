# S2G (Sentence-to-Graph) Codebase Documentation

This document provides a comprehensive, exhaustive technical reference for the **S2G (Sentence-to-Graph)** codebase (`sentinel` branch). It is designed to furnish complete context for developers working on or extending this project.

---

## 1. High-Level Architecture Overview

**S2G** frames joint entity and relation extraction (IE) as a sequence-to-sequence (Text-to-Text) translation problem built upon **Flan-T5** (Base/Large).

By default, S2G uses natural language instruction prompts for the encoder input and generates a linearised token graph using **incrementing sentinel tokens** (`<extra_id_0>`, `<extra_id_1>`, ...) for the decoder output.

```
                            ┌──────────────────────────────────────────────────────────┐
                            │                  Encoder Input (Prompt)                  │
                            │  Extract all entities of type [...] and find relations   │
                            │  of type [...] among the extracted entities.             │
                            │                                                          │
                            │  Text: <Source Text>                                     │
                            └────────────────────────────┬─────────────────────────────┘
                                                         │
                                                         ▼
                                             ┌───────────────────────┐
                                             │    Flan-T5 Encoder    │
                                             └───────────┬───────────┘
                                                         │
                                                         ▼
                                             ┌───────────────────────┐
                                             │    Flan-T5 Decoder    │
                                             └───────────┬───────────┘
                                                         │
                                                         ▼
                            ┌──────────────────────────────────────────────────────────┐
                            │            Decoder Output (Nested Graph)                 │
                            │  <extra_id_0> e1 <e_type> type <r_type> rel <extra_id_1> │
                            │  e2 <nr_type> rel2 <extra_id_2> e3                       │
                            └────────────────────────────┬─────────────────────────────┘
                                                         │
                                                         ▼
                                             ┌───────────────────────┐
                                             │   Deterministic       │
                                             │   Graph Parser &      │
                                             │   Evaluator           │
                                             └───────────────────────┘
```

### Core Concepts

1. **Prompt**: The encoder prompt formats the input text with task instructions and target entity/relation schema types. By default, natural language prompts are used (e.g. `"Extract all entities of type [...] and find relations of type [...] among the extracted entities. Text: ..."`). Alternatively, a special-token schema format (`prompt: ssi`, using `<extra_id_0>` for entity types, `<extra_id_1>` for relation types, and `<extra_id_2>` before source text) is also supported.
2. **Graph (Sentinel Scheme)**: The linearised target string generated by the decoder. Entities in text offset order are prefixed by sequential incrementing sentinel tokens (`<extra_id_0>`, `<extra_id_1>`, `<extra_id_2>`, ...).
3. **Vocabulary Special Tokens**: Explicit special tokens `<e_type>`, `<r_type>`, `<nr_type>`, and `<null>` are added to the tokenizer vocabulary.
4. **Supported Model Variants**:
   * **`joint`**: Predicts entity text spans, entity types, and typed relations between entities in a nested structure.
   * **`boundary_joint`**: Predicts entity text spans and relations between entities (without entity types) in a nested structure.
   * **`re`**: Relation extraction given head and tail entity texts and their entity types.
   * **`boundary_re`**: Relation extraction between entity text spans without entity types.
5. **Rejection & Null Blocks**: Optional negative schema type markers (`<null> type`) included in Graph outputs to force explicit model rejection of absent entity or relation types.

## 2. Module: `s2g.linearisation`

The `linearisation` package defines the special token mapping, graph linearisation into Graph strings, Graph parsing logic back to structured graph blocks, and encoder prompt building.

---

### 2.1. `s2g/linearisation/special_tokens.py`

#### Purpose
Defines the special token registry, vocabulary expansion, sentinel token string generation, and embedding initialization ("warm starting") for special tokens.

#### Constants & Token Map
* `ALL_TOKEN_NAMES`: `['e_type', 'r_type', 'nr_type', 'null']`
* `VALID_VARIANTS`: `{'re', 'boundary_re', 'boundary_joint', 'joint'}`

#### Special Token Mapping (`S2GTokens.token_strs`)
| Token Key | Vocabulary Special Token String | Semantic Role |
|---|---|---|
| `'e_type'` | `<e_type>` | Entity type token in Graph |
| `'r_type'` | `<r_type>` | Triplet relation type token in Graph |
| `'nr_type'` | `<nr_type>` | Nested relation type token (for same head entity) in Graph |
| `'null'` | `<null>` | Standalone negative rejection marker token in Graph |

#### Sentinel Tokens Helper
* `S2GTokens.sentinel_token(idx: int) -> str`: Returns `<extra_id_{idx}>` for entity at position `idx`.

#### Key Classes & Functions

##### `S2GTokens(variant: str, use_rejection: bool = False, prompt: str = 'natural')`
* **`base_tok_map`**: Maps active tokens per variant (`re`, `boundary_re`, `boundary_joint`, `joint`).
* **`self.active_tokens`**: Active token set for configured variant. Adds `'null'` if `use_rejection=True`.
* **`self.all_tokens`**: List of vocabulary special token strings (`['<e_type>', '<r_type>', '<nr_type>', '<null>']`).

##### `add_special_tokens_to_tokenizer(tokenizer, tokens: S2GTokens, model=None, warm_start: bool = True) -> int`
* Adds `tokens.all_tokens` to HuggingFace tokenizer via `add_special_tokens({'additional_special_tokens': ...})`.
* If `model` is provided and tokens were added:
  * Sets `model.config.tie_word_embeddings = False`.
  * Resizes model token embeddings via `model.resize_token_embeddings(len(tokenizer))`.
* If `warm_start=True`: Initializes new token embeddings by averaging input/output embeddings of natural language phrases:
  * `'e_type'` $\rightarrow$ `"entity type: "`
  * `'r_type'` $\rightarrow$ `"relation: "`
  * `'nr_type'` $\rightarrow$ `"next relation: "`
  * `'null'` $\rightarrow$ `"not found: "`

##### `get_token_ids(tokenizer, tokens: S2GTokens) -> Dict[str, int]`
* Returns a map from token keys to integer token IDs in the tokenizer.

### 2.2. `s2g/linearisation/graph.py`

#### Purpose
Handles graph building (converting raw entity/relation JSON dicts into linearised Graph strings with incrementing sentinels) and graph parsing (reconstructing structured entity and relation blocks from linearised Graph text).

#### Data Structures & Types
* `EntityBlock`: `Dict[str, Any]` containing `'text'`, `'type'` (optional), and `'relations'` (`List[Dict[str, Any]]` where each relation is `{'type': rel_type, 'tail_id': tail_idx}`).
* `Triplet`: `Tuple[int, str, int]` $\rightarrow$ `(head_idx, rel_type, tail_idx)`.
* `RejectedItem`: `str` label representing a rejected (null) schema type.

#### Key Functions

##### `organise_filter_and_block(entities: List, relations: List, allowed_ent_types: Set[str], allowed_rel_types: Set[str]) -> List[EntityBlock]`
1. Filters `entities` by `allowed_ent_types`.
2. Filters `relations` by `allowed_rel_types` and ensures both head and tail entity offsets are present in filtered entities.
3. Sorts entities by `offset` `[start, end]`.
4. Maps tail entity offsets to position indices `offset_to_idx`.
5. Packs entities into `EntityBlock` instances with relation items containing `'tail_id'`.

##### `build_graph(ent_blocks, variant, tokens, use_nesting=True, random_graph=False, use_rejection=False, rejected_ent_types=None, rejected_rel_types=None) -> str`
* Constructs the linearised Graph target string using incrementing sentinels `<extra_id_{idx}>`.
* **Variant `joint` / `boundary_joint` (Nested)**:
  * Iterates through entity blocks in text offset order.
  - Emits `<extra_id_{idx}> text [<e_type> type]`.
  - Nests relations directly after entity type: `<r_type> rel_type <extra_id_{tail_idx}> tail_text` (subsequent relations use `<nr_type>`).
* **Variant `re` / `boundary_re`**:
  * Emits head entities with relations: `<extra_id_{idx}> text [<e_type> type] <r_type> rel_type <extra_id_{tail_idx}> tail_text [<e_type> tail_type]`.
* **Null Rejection Block**: Appends `<null> type` for each rejected type.

##### `parse_graph(text: str, tok: S2GTokens, use_nesting: bool = True) -> Tuple[List[EntityBlock], List[RejectedItem]]`
* Parses Graph text using a state-machine parser.
* Allocates entities directly into a position-indexed `entities` list based on `<extra_id_i>` integer index $i$.
* Eliminates entity deduplication since each entity has a unique sentinel token ID.
* Reconstructs relation items as `{'type': rel_type, 'tail_id': tail_idx}`.

##### `extract_triplets(entities: List[EntityBlock], include_types: bool = False) -> List[Triplet]`
* Flattens entity blocks into position-indexed triplets `(head_idx, rel_type, tail_id)`.

## 3. Module: `s2g.data`

The `data` package handles dataset loading, memory-mapped JSONL indexing, dynamic schema sampling, batch collation, and raw dataset preprocessing for benchmark datasets (CoNLL04, SciERC, NYT).

---

### 3.1. `s2g/data/dataset.py`

#### Purpose
Provides `S2GDataset`, a PyTorch `Dataset` backed by memory-mapped file handles (`mmap`) and vectorized line offset indexing.

---

### 3.2. `s2g/data/collator.py`

#### Purpose
`S2GCollator` formats raw dataset instances into tokenized model batches (`input_ids`, `attention_mask`, `labels`).

---

## 4. Module: `s2g.evaluation`

The `evaluation` package provides corpus-level and per-type macro metric calculation functions as well as the streaming `S2GEvaluator`.

---

### 4.1. `s2g/evaluation/metrics.py`

#### Purpose
Computes precision, recall, and F1 metrics matching standard benchmarks and REBEL evaluation protocols using position index evaluation.

#### Core Extraction & Metric Functions

##### `extract_from_blocks(blocks: List[EntityBlock])`
Single-pass extraction returning four lists for a sentence:
1. `triplets`: List of `(head_idx, rel_type, tail_idx)`
2. `quintuples`: List of `(head_idx, head_type, rel_type, tail_idx, tail_type)`
3. `entities`: List of integer position indices `[head_idx]`
4. `mentions`: List of `(head_idx, entity_type)` tuples

##### `compute_metrics_for_variant(variant, all_pred_blocks, all_gold_blocks, rel_schema, ent_schema) -> Dict[str, float]`
Computes variant-appropriate metrics based on index matching across predicted and gold entity blocks.

---

### 4.2. `s2g/evaluation/evaluator.py`

#### Purpose
`S2GEvaluator` provides streaming evaluation over DataLoaders and JSONL prediction dumping.

---

## 5. Summary Matrix of Module Responsibilities

| Package / File | Primary Responsibility |
|---|---|
| `s2g.linearisation.special_tokens` | Token registry for `<e_type>`, `<r_type>`, `<nr_type>`, `<null>`, and sentinel helper `S2GTokens.sentinel_token(idx)`. |
| `s2g.linearisation.graph` | Graph construction (`build_graph`), state-machine parsing (`parse_graph`), block filtering (`organise_filter_and_block`). |
| `s2g.linearisation.prompt` | Encoder input prompt construction for natural language instructions and SSI schema. |
| `s2g.data.dataset` | Memory-mapped (`mmap`) JSONL reader with vectorized offset indexing. |
| `s2g.data.collator` | Batch collation and dynamic schema sampling schedules (`budget` vs `bernoulli`). |
| `s2g.evaluation.metrics` | Micro and per-type macro PRF metric calculation using position-indexed tuple matching. |
| `s2g.evaluation.evaluator` | Streaming evaluation harness and DataLoader decoder. |
| `s2g.training.trainer` | Custom `S2GTrainer` with inverse sqrt LR scheduler and evaluation loader overrides. |
| `s2g.training.callbacks` | Step tracking, W&B generation table logging, resumable metadata checkpointing. |
| `s2g.scripts.train` | Main training pipeline script. |
| `s2g.scripts.evaluate` | Standalone evaluation script. |
