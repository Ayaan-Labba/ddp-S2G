# S2G (Sentence-to-Graph) Codebase Documentation

This document provides a comprehensive, exhaustive technical reference for the **S2G (Sentence-to-Graph)** codebase. It is designed to furnish complete context for LLMs or developers working on or extending this project.

---

## 1. High-Level Architecture Overview

**S2G** frames joint entity and relation extraction (IE) as a sequence-to-sequence (Text-to-Text) translation problem built upon **Flan-T5** (Base/Large).

By default, S2G uses natural language instruction prompts for the encoder input and generates a linearised token graph for the decoder output.

```
                            ┌──────────────────────────────────────────────────────────┐
                            │                  Encoder Input (Prompt)                  │
                            │  Extract all entities of type [...] and find relations   │
                            │  of type [...] among the extracted entities.             │
                            │                                                          │
                            │  Text: <Source Text>                                     │
                            └────────────────────────────┬─────────────────────────────┘
                                                         │
                                                         ▼
                                             ┌───────────────────────┐
                                             │    Flan-T5 Encoder    │
                                             └───────────┬───────────┘
                                                         │
                                                         ▼
                                             ┌───────────────────────┐
                                             │    Flan-T5 Decoder    │
                                             └───────────┬───────────┘
                                                         │
                                                         ▼
                            ┌──────────────────────────────────────────────────────────┐
                            │                  Decoder Output (Graph)                  │
                            │  <extra_id_3> head <extra_id_4> e_type                   │
                            │  <extra_id_5> head <extra_id_6> r_type <extra_id_8> tail │
                            └────────────────────────────┬─────────────────────────────┘
                                                         │
                                                         ▼
                                             ┌───────────────────────┐
                                             │   Deterministic       │
                                             │   Graph Parser &      │
                                             │   Evaluator           │
                                             └───────────────────────┘
```

### Core Concepts

1. **Prompt**: The encoder prompt formats the input text with task instructions and target entity/relation schema types. By default, natural language prompts are used (e.g. `"Extract all entities of type [...] and find relations of type [...] among the extracted entities. Text: ..."`). Alternatively, a special-token schema format (`prompt: ssi`, using `<extra_id_0>` for entity types, `<extra_id_1>` for relation types, and `<extra_id_2>` before source text) is also supported.
2. **Graph**: The linearised target string generated by the decoder, representing entities, entity types, and head-rel-tail triplets via special tokens (`<extra_id_3>` through `<extra_id_8>`).
3. **Supported Model Variants**:
   * **`joint`**: Predicts entity text spans, entity types, and typed relations between entities.
   * **`boundary_joint`**: Predicts entity text spans and relations between entities (without entity types).
   * **`re`**: Relation extraction given head and tail entity texts and their entity types.
   * **`boundary_re`**: Relation extraction between entity text spans without entity types.
4. **Rejection & Null Blocks**: Optional negative schema type markers (`<extra_id_9>`) included in Graph outputs to force explicit model rejection of absent entity or relation types.

## 2. Module: `s2g.linearisation`

The `linearisation` package defines the special token mapping, graph linearisation into Graph strings, Graph parsing logic back to structured graph blocks, and encoder prompt building.

---

### 2.1. `s2g/linearisation/special_tokens.py`

#### Purpose
Defines the special token registry, token-to-variant mapping, model vocabulary expansion, and embedding initialization ("warm starting") for special tokens.

#### Constants & Token Map
* `ALL_TOKEN_NAMES`: `['ner', 're', 'text', 'ent', 'e_type', 'head', 'r_type', 'nr_type', 'tail', 'null']`
* `VALID_VARIANTS`: `{'re', 'boundary_re', 'boundary_joint', 'joint'}`

#### Special Token Mapping (`S2GTokens.token_strs`)
| Token Key | HuggingFace Special Token String | Semantic Role |
|---|---|---|
| `'ner'` | `<extra_id_0>` | Prefix marker for entity schema in Prompt (when `prompt: ssi`) |
| `'re'` | `<extra_id_1>` | Prefix marker for relation schema in Prompt (when `prompt: ssi`) |
| `'text'` | `<extra_id_2>` | Marker preceding source text in Prompt (when `prompt: ssi`) |
| `'ent'` | `<extra_id_3>` | Entity start token in Graph |
| `'e_type'` | `<extra_id_4>` | Entity type token in Graph |
| `'head'` | `<extra_id_5>` | Triplet head/subject entity start token in Graph |
| `'r_type'` | `<extra_id_6>` | Triplet relation type token in Graph |
| `'nr_type'` | `<extra_id_7>` | Nested relation type token (for same head entity) in Graph |
| `'tail'` | `<extra_id_8>` | Triplet tail/object entity token in Graph |
| `'null'` | `<extra_id_9>` | Negative rejection marker token in Graph |

#### Key Classes & Functions

##### `S2GTokens(variant: str, use_rejection: bool = False, prompt: str = 'natural')`
* **`base_tok_map` & `ssi_tok_map`**: Subsets `ALL_TOKEN_NAMES` depending on whether `prompt=='ssi'` and the variant (`re`, `boundary_re`, `boundary_joint`, `joint`).
* **`self.active_tokens`**: Set of active token keys for the configured variant and prompt. Adds `'null'` if `use_rejection=True`.
* **`self.all_tokens`**: List of string representations (`<extra_id_X>`) for active tokens.

##### `add_special_tokens_to_tokenizer(tokenizer, tokens: S2GTokens, model=None, warm_start: bool = True) -> int`
* Adds `tokens.all_tokens` to the HuggingFace tokenizer via `add_special_tokens({'additional_special_tokens': ...})`.
* If `model` is provided and tokens were added:
  * Sets `model.config.tie_word_embeddings = False`.
  * Resizes model token embeddings via `model.resize_token_embeddings(len(tokenizer))`.
* If `warm_start=True`: Initializes new token embeddings by averaging input/output embeddings of natural language phrases:
  * `'ner'` $\rightarrow$ `"find entities: "`
  * `'re'` $\rightarrow$ `"find relations: "`
  * `'text'` $\rightarrow$ `"text: "`
  * `'ent'` $\rightarrow$ `"entity: "`
  * `'e_type'` $\rightarrow$ `"entity type: "`
  * `'head'` $\rightarrow$ `"subject: "`
  * `'r_type'` $\rightarrow$ `"relation: "`
  * `'nr_type'` $\rightarrow$ `"next relation: "`
  * `'tail'` $\rightarrow$ `"object: "`
  * `'null'` $\rightarrow$ `"not found: "`

##### `get_token_ids(tokenizer, tokens: S2GTokens) -> Dict[str, int]`
* Returns a map from token keys (`'head'`, `'tail'`, etc.) to integer token IDs in the tokenizer.
* Returns fallback negative integer IDs (`-(idx + 200)`) for inactive token keys.

### 2.2. `s2g/linearisation/graph.py`

#### Purpose
Handles graph building (converting raw entity/relation JSON dicts into linearised Graph strings) and graph parsing (reconstructing structured entity and relation blocks from linearised Graph text).

#### Data Structures & Types
* `EntityBlock`: `Dict[str, Any]` containing `'text'`, `'type'` (optional), and `'relations'` (list of relation dicts).
* `Triplet`: `Tuple[str, str, str]` $\rightarrow$ `(head_text, rel_type, tail_text)`.
* `RejectedItem`: `str` label representing a rejected (null) schema type.

#### Key Functions

##### `organise_filter_and_block(entities: List, relations: List, allowed_ent_types: Set[str], allowed_rel_types: Set[str]) -> List[EntityBlock]`
1. Filters `entities` by `allowed_ent_types`.
2. Filters `relations` by `allowed_rel_types` and ensures both head and tail entity offsets are present in the filtered entities.
3. Sorts entities by `offset` `[start, end]` and relations by `(head_offset, tail_offset)`.
4. Groups relations by head entity offset and attaches `'relations'` lists to entity blocks.

##### `build_graph(ent_blocks, variant, tokens, use_nesting=True, random_graph=False, use_rejection=False, rejected_ent_types=None, rejected_rel_types=None) -> str`
* Constructs the linearised Graph target string.
* If `random_graph=True`, shuffles entity blocks and relation lists inside blocks.
* **Variant `re` / `boundary_re`**:
  * Emits head entity once followed by relation & tail.
  * If `use_nesting=True` and an entity has multiple relations, subsequent relations use `<extra_id_7>` (`nr_type`) instead of re-emitting `<extra_id_5>` (`head`).
  * `re` variant includes `<extra_id_4>` (`e_type`) for head and tail entities; `boundary_re` omits entity types.
* **Variant `joint` / `boundary_joint`**:
  * **Section 1 (Entity Section)**: Emits all entities first (`<extra_id_3> text [<extra_id_4> type]`).
  * **Section 2 (Triplet Section)**: Emits triplets using `<extra_id_5>` (`head`), `<extra_id_6>` (`r_type`), `<extra_id_8>` (`tail`) and `<extra_id_7>` (`nr_type`).
* **Null Rejection Block**: Appends `<extra_id_9> type` for each type in `rejected_ent_types` and `rejected_rel_types` via `append_null_block()`.

##### `parse_graph(text: str, tok: S2GTokens, use_nesting: bool = True) -> Tuple[List[EntityBlock], List[RejectedItem]]`
* Parses a generated Graph text string using a deterministic finite-state accumulator loop.
* Splitting is powered by regular expressions constructed via `get_compiled_special_token_pattern()`.
* **Joint Parsing States**: `'IDLE'`, `'ENT_TEXT'`, `'ENT_TYPE'`, `'HEAD'`, `'REL'`, `'TAIL'`, `'NULL'`.
* **RE Parsing States**: `'IDLE'`, `'HEAD_TEXT'`, `'HEAD_TYPE'`, `'REL'`, `'TAIL_TEXT'`, `'TAIL_TYPE'`, `'NULL'`.
* Returns `(entities, rejected)`, where `entities` are deduplicated via `deduplicate_entities()`.

##### `extract_triplets(entities: List[EntityBlock], include_types: bool = False) -> List[Triplet]`
* Flattens entity blocks into a list of triplets.
* If `include_types=True`, formats head and tail as `"text [type]"`.

### 2.3. `s2g/linearisation/prompt.py`

#### Purpose
Generates encoder inputs by prepending Prompt schema headers or natural language instructions to the raw text.

#### Functions

##### `build_ent_ssi(ent_types: List[str], variant: str, random_order: bool = False) -> str`
* Joins entity schema types prefixed by `<extra_id_0>` (e.g., `<extra_id_0> Location <extra_id_0> Person`). Used when `prompt='ssi'`.

##### `build_rel_ssi(rel_types: List[str], variant: str, random_order: bool = False) -> str`
* Joins relation schema types prefixed by `<extra_id_1>` (e.g., `<extra_id_1> lives in <extra_id_1> works for`). Used when `prompt='ssi'`.

##### `build_<variant>_encoder_input(...) -> str`
Supported variants: `build_re_encoder_input`, `build_boundary_re_encoder_input`, `build_joint_encoder_input`, `build_boundary_joint_encoder_input`.
* **`prompt == 'natural'`** *(Default)*: Emits natural language prompt instructions:
  * *Joint*: `"Extract all entities of type [t1, t2] and find relations of type [r1, r2] among the extracted entities. \n\n Text: {text}"`
  * *Boundary Joint*: `"Extract all entities and find relations of type [r1, r2] among the extracted entities. Text: {text}"`
  * *RE*: `"Extract all relations of type [r1, r2] among the entities of type [t1, t2] in the given text. Text: {text}"`
  * *Boundary RE*: `"Extract all relations of type [r1, r2] among the entities in the given text. Text: {text}"`
* **`prompt == 'ssi'`**: Emits `"<ent_ssi> <rel_ssi> <extra_id_2> <text>"`.
* **`prompt in {False, 'false', 'False'}`**: Returns raw `text`.

## 3. Module: `s2g.data`

The `data` package handles dataset loading, memory-mapped JSONL indexing, dynamic schema sampling, batch collation, and raw dataset preprocessing for benchmark datasets (CoNLL04, SciERC, NYT).

---

### 3.1. `s2g/data/dataset.py`

#### Purpose
Provides `S2GDataset`, an ultra-fast PyTorch `Dataset` backed by memory-mapped file handles (`mmap`) and vectorized line offset indexing.

#### Key Functions & Classes

##### `_build_offset_index(filepath: Path) -> np.ndarray`
* Scans a JSONL file in 64MB binary chunks (`_SCAN_CHUNK_BYTES = 64 * 1024 * 1024`).
* Vectorized search for newline bytes (`arr == 10`) constructs an `(N, 2)` NumPy array of byte offsets `[start_offset, end_offset]` for every non-empty line.

##### `S2GDataset(filepath: Union[str, Path], subset_fraction: Optional[float] = None, seed: Optional[int] = 0)`
* Loads line offset table without reading the full file into Python memory.
* If `subset_fraction` (0.0 to 1.0) is passed, reproducibly subsamples offset rows using `np.random.default_rng(seed)`.
* `__getitem__(idx)` reads bytes directly from `mmap[start:end]` and parses with `json.loads()`.
* Implements custom `__getstate__` and `__setstate__` to safely pickling across DataLoader worker process forks.

---

### 3.2. `s2g/data/collator.py`

#### Purpose
`S2GCollator` formats raw dataset instances into tokenized model batches (`input_ids`, `attention_mask`, `labels`).

#### Key Operations

##### Schema Sampling Strategies (`sample_types`)
1. **`budget` mode**:
   * Uses all positive instance entity/relation types.
   * Samples negative types from the remaining schema up to `max_ent_types` / `max_rel_types`.
2. **`bernoulli` mode**:
   * Simulates dynamic curriculum/rejection training.
   * Interpolates positive & negative retention rates and maximum counts from training step $t=0$ to $t=T$ via `schedule_values()`:
     * `pos_rate`: lerp(`positive_rate_start`, `positive_rate_end`)
     * `neg_rate`: lerp(`negative_rate_start`, `negative_rate_end`)
     * `pos_k`: lerp(`pos_max_start`, `pos_max_end`)
     * `neg_k`: lerp(`negative_max_start`, `negative_max_end`)

##### Batch Tokenization (`tokenize`)
* Tokenizes encoder inputs (`max_source_length`, padded to longest in batch).
* Tokenizes decoder targets (`max_target_length`, padded to longest in batch).
* Replaces padding token IDs in labels with `-100` so HuggingFace PyTorch models ignore pad tokens during loss calculation.

##### `to_eval_mode() -> S2GCollator`
* Returns a copy of the collator forced to `mode='budget'`, ensuring evaluation batches are collated deterministically without stochastic Bernoulli sampling.

---

### 3.3. Preprocessing Scripts

#### `s2g/data/preprocess_conll04.py`
* Converts SpERT-format CoNLL-04 JSON files (`conll04_train.json`, `conll04_dev.json`, `conll04_test.json`) into `.jsonl` files (`train.jsonl`, `val.jsonl`, `test.jsonl`).
* Maps raw entity and relation type strings using `configs/data/conll04.yaml`.
* Emits `entity.schema` and `relation.schema`.

#### `s2g/data/preprocess_scierc.py`
* Supports both sentence-level and document-level SciERC parsing (`--document_level`).
* Handles document-absolute token offset conversions.
* Retains entity-less and relation-less instances (matching REBEL behavior).
* Maps labels using `configs/data/scierc.yaml` and writes `entity.schema` and `relation.schema`.

#### `s2g/data/preprocess_nyt.py`
* Converts NYT-multi (JointRE repository format) into `.jsonl`.
* Sorts relation triples by head entity token start index (`details[0]`).
* Maps relation labels using `configs/data/nyt.yaml` and writes schema files.

## 4. Module: `s2g.evaluation`

The `evaluation` package provides corpus-level and per-type macro metric calculation functions as well as the streaming `S2GEvaluator`.

---

### 4.1. `s2g/evaluation/metrics.py`

#### Purpose
Computes precision, recall, and F1 metrics matching standard benchmarks and the REBEL evaluation protocol.

#### Core Extraction & Metric Functions

##### `extract_from_blocks(blocks: List[EntityBlock])`
Single-pass extraction returning four lists for a sentence:
1. `triplets`: List of `(head_text, rel_type, tail_text)`
2. `quintuples`: List of `(head_text, head_type, rel_type, tail_text, tail_type)`
3. `entities`: List of entity text strings `[text]`
4. `mentions`: List of `(entity_text, entity_type)` tuples

##### `corpus_prf(all_predicted, all_gold, prefix: str) -> Dict[str, float]`
* Micro-averaged Precision, Recall, and F1 across all sentences.
* Returns `{ "{prefix}_precision": P, "{prefix}_recall": R, "{prefix}_f1": F1 }`.

##### `per_type_macro(all_predicted, all_gold, type_fn, schema: List[str], prefix: str) -> Dict[str, float]`
* Macro-averaged PRF computed REBEL-style:
  1. Computes micro PRF per schema type $t \in \text{schema}$ across all sentences.
  2. Averages precision, recall, and F1 values across all schema types $N = |\text{schema}|$.
* Out-of-schema (hallucinated) predictions are discarded prior to score calculation.
* Returns `{ "macro_{prefix}_precision": P, "macro_{prefix}_recall": R, "macro_{prefix}_f1": F1 }`.

##### `compute_metrics_for_variant(variant, all_pred_blocks, all_gold_blocks, rel_schema, ent_schema) -> Dict[str, float]`
Computes variant-appropriate metrics:
* **`joint`**: `ner_boundary` (micro), `ner` (micro + macro), `boundary` (micro + macro), `strict` (micro + macro).
* **`boundary_joint`**: `ner_boundary` (micro), `boundary` (micro + macro).
* **`re`**: `ner_boundary` (micro), `ner` (micro + macro), `boundary` (micro + macro), `strict` (micro + macro).
* **`boundary_re`**: `ner_boundary` (micro), `boundary` (micro + macro).

---

### 4.2. `s2g/evaluation/evaluator.py`

#### Purpose
`S2GEvaluator` provides text cleaning, batch prediction decoding, Graph parsing, metric evaluation, and memory-efficient streaming evaluation over a PyTorch `DataLoader`.

#### Key Methods

##### `clean_text(text: str) -> str`
Strips tokenizer control tokens (`<pad>`, `</s>`, `<s>`) and normalizes whitespace.

##### `parse_text(text: str) -> Tuple[List[EntityBlock], List[Any]]`
Cleans text and calls `parse_graph(cleaned, tok=self.tokens)`.

##### `process_batch_predictions(batch_instances, generated_ids) -> Tuple[List[List[EntityBlock]], List[Dict[str, Any]]]`
Decodes model-generated token IDs, parses Graph blocks, and constructs per-instance output prediction records.

##### `run_evaluation(dataset, split, dataloader, out_dir, model, max_target_length, num_beams, device, constraint_decoding=False, ...)`
* Iterates through `dataloader` in streaming mode.
* Optionally attaches `build_constraint_processor(...)` if `constraint_decoding=True`.
* Generates output using `model.generate()`.
* Flushes individual JSONL prediction records to `out_dir / f"{split}_results.jsonl"` to keep memory consumption constant.
* Computes final corpus metrics and saves to `out_dir / f"{split}_metrics.json"`.

---

## 5. Module: `s2g.training`

The `training` package extends HuggingFace `Seq2SeqTrainer` and defines custom callbacks for logging, checkpointing, and step synchronization.

---

### 5.1. `s2g/training/trainer.py`

#### Purpose
`S2GTrainer` inherits from HuggingFace `Seq2SeqTrainer` to customize learning rate schedulers, evaluation dataloaders, and validation step handling.

#### Custom Functionality

##### Inverse Square Root Scheduler (`create_scheduler`)
* Supports `args.lr_scheduler_type == 'inverse_sqrt'`.
* Linear warmup for $step < warmup\_steps$, followed by $\text{lr} \times \sqrt{\frac{warmup\_steps}{step}}$.

##### Evaluation DataLoader Override (`get_eval_dataloader`)
* Forces `collator.to_eval_mode()`, guaranteeing evaluation runs in deterministic `budget` mode.

##### Dual Validation Evaluation (`evaluate`)
* Evaluates on the primary validation dataset (`val.jsonl`).
* If `eval_train_dataset` is passed, temporarily strips `EarlyStoppingCallback` and evaluates on a subsample of the training set under key prefix `'train'`, allowing monitoring of train/val generalization gaps.

##### Metric Computation Adapter (`compute_metrics_hf`)
* Decodes model predictions and label IDs, parses Graph outputs via `evaluator.parse_text()`, and calculates metrics via `evaluator.compute_final_metrics()`.

---

### 5.2. `s2g/training/callbacks.py`

#### Purpose
Custom `TrainerCallback` subclasses used during training.

#### Classes

##### `StepTrackingCallback(collator: S2GCollator)`
* Updates `collator.current_step = state.global_step` at the end of every training step to synchronize Bernoulli sampling schedules.

##### `GenerateTextSamplesCallback`
* Logs formatted prediction tables (`Source`, `Encoder Input`, `Predicted Entities`, `Gold Entities`, `Predicted Triplets`, `Gold Triplets`, `Predicted Graph`, `Gold Graph`) to Weights & Biases (`wandb`) at periodic step intervals (`interval`).

##### `PeriodicCheckpointCallback`
* Triggers checkpoint saving every `every_n_steps` and saves `run_metadata.json` containing `wandb_run_id` for resume capability.

##### `S2GEarlyStoppingCallback(EarlyStoppingCallback)`
* Prevents early stopping patience counter from incrementing if `best_metric` is still $\le 0.0$.

##### `load_run_metadata(output_dir: str) -> Optional[Dict[str, Any]]`
* Helper to read `wandb_run_id` from `output_dir / "run_metadata.json"`.

---

## 6. Module: `s2g.scripts`

The `scripts` package contains entry-point CLI utilities for training, evaluation, VRAM measurement, and dataset length analysis.

---

### 6.1. `s2g/scripts/config_utils.py`

#### Purpose
Defines the hierarchical dataclass schema for OmegaConf configuration management.

#### Dataclass Hierarchy (`S2GConfig`)
* `DataConfig`: `data_dir`, `rel_schema`, `ent_schema`, `output_dir`
* `ModelConfig`: `name`, `pretrained_checkpoint`, `variant` (`'joint'`, `'boundary_joint'`, `'re'`, `'boundary_re'`)
* `TokenizerConfig`: `max_source_length`, `max_target_length`
* `PromptConfig`: `mode` (`'budget'`/`'bernoulli'`), `type` (`'natural'`/`'ssi'`), `random_prompt`, `max_ent_types`, `max_rel_types`, linear interpolation rates (`pos_rate_start`, `pos_rate_end`, `neg_rate_start`, `neg_rate_end`, `pos_max_start`, `pos_max_end`, `neg_max_start`, `neg_max_end`)
* `GraphConfig`: `random_graph`, `use_rejection`, `use_nesting`
* `OptimizerConfig`: `optim` (`'adamw_torch'`, `'adamw_bnb_8bit'`), `lr`, `weight_decay`, `adam_beta1`, `adam_beta2`, `adam_epsilon`
* `SchedulerConfig`: `type` (`'cosine'`, `'constant'`, `'inverse_sqrt'`), `warmup_steps`
* `TrainConfig`: `max_steps`, `steps_per_log`, `batch_size`, `gradient_acc_steps`, `gradient_clip_value`, `gradient_checkpointing`, `precision` (`'bf16'`, `'fp16'`, `'fp32'`), `seed`, `warm_start`
* `ValidationConfig`: `check_interval`, `percent_check`, `train_percent_check`, `batch_size`, `num_beams`, `early_stopping_patience`, `early_stopping_metric`
* `GenerationConfig`: `num_beams`, `constraint_decoding`, `length_penalty`, `early_stopping`, `no_repeat_ngram_size`
* `EvaluationConfig`: `split`, `batch_size`
* `CheckpointConfig`: `save_top_k`, `every_n_steps`, `resume_from`
* `CallbacksConfig`: `sample_generation_interval`
* `WandbConfig`: `project`, `entity`, `run_name`
* `HardwareConfig`: `num_workers`, `persistent_workers`, `gpu_ids`

#### Config Loading Functions
* `load_config() -> DictConfig`: Parses `--config <path>` flag and applies command-line dotlist overrides (e.g. `optimizer.lr=1e-4`).
* `load_schema(schema_path: str) -> List[str]`: Reads line-separated schema files.

---

### 6.2. `s2g/scripts/measure_lengths.py`

#### Purpose
Scans dataset splits (`train.jsonl`, `val.jsonl`, `test.jsonl`) to compute token length percentiles ($p50, p75, p90, p95, p99, \max$) for source encoder inputs (Prompt) and target sequences (Graph).

#### Execution
`python -m s2g.scripts.measure_lengths --config configs/finetune.yaml`
Outputs suggested `max_source_length` and `max_target_length` rounded up to multiples of 32 based on $p99$.

---

### 6.3. `s2g/scripts/measure_vram.py`

#### Purpose
Determines maximum trainable and evaluable batch sizes before encountering Out-Of-Memory (OOM) errors on the target GPU.

#### Key Routines
* `binary_search_max_train_batch(...)`: Binary searches maximum training batch size fitting forward + backward passes.
* `_populate_optimizer_states(...)`: Runs a dummy optimizer step to keep AdamW optimizer moment tensors resident in VRAM.
* `binary_search_max_eval_batch(...)`: Binary searches maximum evaluation batch size fitting `model.generate()` with resident optimizer states.

---

### 6.4. `s2g/scripts/evaluate.py`

#### Purpose
Standalone CLI entry point for model evaluation.

#### Execution Flow
1. Loads configuration using `load_config()`.
2. Reads model checkpoint and auto-detects model variant from `checkpoint/variant.txt`.
3. Loads tokenizer, model, and active `S2GTokens`.
4. Constructs `S2GDataset` and `DataLoader` using budget-mode collator.
5. Invokes `S2GEvaluator.run_evaluation()` to compute metrics and stream predictions to disk.

---

### 6.5. `s2g/scripts/train.py`

#### Purpose
Unified entry point for pre-training and fine-tuning S2G models.

#### Detailed Execution Workflow

```
 1. Load OmegaConf Config (load_config) & Set Random Seeds (set_seed)
 2. Initialize WandB Run & Save config.yaml to Output Dir
 3. Load S2GDataset for train.jsonl and val.jsonl (with optional train/val subsampling)
 4. Load Schema Files (relation.schema & entity.schema)
 5. Load Pre-trained Tokenizer & AutoModelForSeq2SeqLM
 6. Configure Special Tokens & Warm-Start Embeddings (add_special_tokens_to_tokenizer)
 7. Initialize S2GCollator & Training Callbacks
 8. Construct Seq2SeqTrainingArguments
 9. Instantiate S2GTrainer & Start Training (trainer.train)
10. Save Best Model Checkpoint & variant.txt to output_dir / "best_model"
11. Run Final Streaming Evaluation on Val & Test Sets and Log to WandB
```

## 7. Config Files Directory (`configs/`)

The `configs/` directory contains base configuration templates and benchmark task overrides.

### 7.1. Base Configurations

* **`configs/pretrain.yaml`**: Pre-training configuration on large datasets (REBEL). Uses Flan-T5 Large, `bf16`, Bernoulli schema sampling mode (`mode: bernoulli`), prompt type `ssi`, max steps 240,000.
* **`configs/finetune.yaml`**: Benchmark fine-tuning defaults. Uses Flan-T5 Base, `bf16`, budget schema sampling mode (`mode: budget`), prompt type `natural` (default), max steps 20,000.
* **`configs/evaluate.yaml`**: Standalone evaluation config. Configures beam search (`num_beams: 3`) and optional constraint decoding (`constraint_decoding: true`).

### 7.2. Dataset Label Mapping Configs (`configs/data/`)

* **`configs/data/conll04.yaml`**: Mapping for CoNLL-04 entity types (`Loc` $\rightarrow$ `location`, `Org` $\rightarrow$ `organization`, `Peop` $\rightarrow$ `person`) and relation types (`Kill` $\rightarrow$ `killed`, `Live_In` $\rightarrow$ `lives in`, etc.).
* **`configs/data/scierc.yaml`**: Mapping for SciERC entity types (`Material`, `Method`, `Task`, etc.) and relation types (`USED-FOR`, `FEATURE-OF`, etc.).
* **`configs/data/scierc_doc.yaml`**: Document-level SciERC configuration mapping.
* **`configs/data/nyt.yaml`**: Mapping for NYT-multi relation types.

### 7.3. Task & Variant Hyperparameters (`configs/variants/`)

Contains fine-tuned configurations tailored to specific variant $\times$ dataset combinations:
* `configs/variants/joint/{conll04.yaml, nyt.yaml}`
* `configs/variants/boundary_joint/{conll04.yaml, nyt.yaml}`
* `configs/variants/re/{conll04.yaml, conll04_eval.yaml, nyt.yaml}`
* `configs/variants/boundary_re/{conll04.yaml, nyt.yaml}`

## Summary Matrix of Module Responsibilities

| Package / File | Primary Responsibility |
|---|---|
| `s2g.linearisation.special_tokens` | Token string definitions (`<extra_id_0..9>`), variant mapping, embedding warm-start initialization. |
| `s2g.linearisation.graph` | Graph string construction (`build_graph`), deterministic multi-state parsing (`parse_graph`), block filtering. |
| `s2g.linearisation.prompt` | Encoder input prompt construction for natural language instructions (default) and special tokens (`prompt: ssi`). |
| `s2g.data.dataset` | Memory-mapped (`mmap`) JSONL reader with vectorized NumPy offset indexing and subset sampling. |
| `s2g.data.collator` | Batch collation, dynamic schema sampling (`budget` vs `bernoulli` schedules), padding mask (`-100`) setup. |
| `s2g.data.preprocess_*` | Raw benchmark converters (CoNLL04, SciERC, NYT) to `.jsonl` and `.schema` files. |
| `s2g.evaluation.metrics` | Micro-average and REBEL-style macro-average PRF calculators for entity boundaries, strict entities, relation boundaries, and strict relations. |
| `s2g.evaluation.evaluator` | `S2GEvaluator` class for text cleaning, batch processing, and memory-efficient streaming evaluation over DataLoaders. |
| `s2g.training.trainer` | Custom `S2GTrainer` with inverse sqrt LR scheduler, budget-mode evaluation dataloader enforcement, and dual train/val evaluation. |
| `s2g.training.callbacks` | Training step counter synchronization, W&B sample generation tables, resumable metadata checkpoints, early stopping guards. |
| `s2g.scripts.config_utils` | `S2GConfig` dataclass schema definitions, CLI dotlist merge parser, schema file loaders. |
| `s2g.scripts.measure_lengths` | Percentile length buffer scanner ($p50 \dots p100$) for source (Prompt) and target (Graph) sequence budgets. |
| `s2g.scripts.measure_vram` | Binary search estimator for maximum GPU train/eval batch sizes with resident optimizer state simulation. |
| `s2g.scripts.evaluate` | Standalone evaluation execution script. |
| `s2g.scripts.train` | Main training pipeline script orchestrating dataset loading, token initialization, trainer setup, and post-training evaluation. |
